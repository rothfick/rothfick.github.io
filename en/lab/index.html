Smaller work: experiments, coursework and research threads.

  • L1

    RAG experiments

    Status: Research

    Evidence. Exploratory work; no results published. Findings feed the AI Reliability Lab.

    Small, isolated experiments on the parts of a RAG pipeline that most often decide answer quality. Each one starts from an evaluation question rather than a demo.

    Explores

    • –How does chunking strategy change what the retriever can find?
    • –When do embeddings retrieve semantically close but wrong passages?
    • –How should retrieved context be ordered and cited in the prompt?
    • –Which failures can a deterministic check catch before an LLM judge is needed?

    Chunking, retrieval, embeddings, prompt construction, evaluation

  • L2

    AI agent experiments

    Status: Research

    Evidence. Exploratory work feeding the Agentic Automation Lab; no results published.

    Minimal agents built to observe one behavior at a time: tool selection, memory, multi-step workflows and how to evaluate each.

    Explores

    • –How reliably does an agent choose between similar tools?
    • –What state must be explicit rather than left in the prompt?
    • –How do you verify that a multi-step workflow actually completed?

    Tools, memory, workflows, evaluation

  • L3

    SOLID / OOP architecture

    Status: Coursework

    Evidence. Coursework. Listed for context, not presented as a product.

    Python exercises in object-oriented design from postgraduate studies: applying SOLID principles, designing class responsibilities, modeling with UML and covering the result with unit tests.

    Explores

    • –Refactoring toward the open/closed and dependency inversion principles
    • –Liskov substitution in practical class hierarchies
    • –Design patterns: creational, structural, behavioral
    • –Unit testing as a design check

    Python, OOP, SOLID, UML, design patterns, unit testing

    Automation experiments

    Status: Engineering lab

    Evidence. Patterns used in the Resilience Framework and in this site's own test suite.

    Explores

    • –Condition-based waiting instead of fixed delays
