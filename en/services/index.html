Services

Concrete problems I can help with. Each service links to the project that shows how I approach it.

  • 01

    AI Quality Audit

    Find failures before your users do.

    I review how your LLM or RAG feature can fail, build an evaluation set from real cases, and set up automated checks so the next prompt, model or retrieval change is accepted on evidence — not on a quick demo.

    You get

    • –A failure-mode review of your feature
    • –A versioned evaluation set seeded from real usage
    • –Automated evaluators with declared thresholds
    • –A regression check wired into your CI

    Typically covers: Hallucination and groundedness testing, retrieval evaluation, prompt and model regression, output schema validation, evaluation datasets.

    Related project

    AI Reliability Evaluation Lab 

    How do you know whether your AI system improved — or silently regressed?

  • 02

    AI Automation

    Automate the repetitive work.

    I start with the workflow, not the model. Deterministic code handles what it can, AI handles what genuinely needs judgment, and a human approves what is uncertain or irreversible.

    You get

    • –A map of which steps are deterministic, AI-assisted or human-approved
    • –A working automation with logging and failure handling
    • –An evaluation set to check it keeps working

    Typically covers: Document workflows, email automation, classification and data extraction, API workflows, human approval steps.

    Related project

    Agentic Automation Lab 

    What does it take for a tool-using agent to be reliable enough to trust with real work?

  • 03

    RAG & internal AI

    Answers you can trace to a source.

    Most RAG failures happen before the model writes a word: the wrong passage is retrieved, the right one is missing, or sources conflict. I help teams design retrieval they can measure and answers they can trace back to a source, with retrieval evaluated separately from generation.

    You get

    • –Retrieval evaluated separately from generation
    • –Answers with citations to source versions
    • –A regression suite for future changes

    Typically covers: Documentation assistants, internal knowledge search, customer support assistants, document analysis.

    Related project

    AI Reliability Evaluation Lab 

    How do you know whether your AI system improved — or silently regressed?

  • 04

    AI product engineering

    Build a product with clear AI boundaries.

    I design the domain first, keep core logic testable without a live model, and put AI behind a gateway that validates every output. The product survives model and vendor changes.

    You get

    • –An architecture with clear AI boundaries
    • –A working MVP with real tests
    • –A documented path from local to production

    Typically covers: Domain modeling, model gateways, structured outputs, cost and feature governance, test strategy.

    Related project

    Learning OS 

    What does the learner actually know — and what evidence supports that claim?

  • 05

    Automation architecture

    Repeatable checks for every release.

    Years of building and leading automation work, applied to your stack: test architecture, quality gates and suites that validate the boundaries where systems actually fail.

    You get

    • –A test architecture mapped to risk and cost
    • –Gates rolled out without blocking teams
    • –Suites your team can maintain

    Typically covers: Playwright and Java automation, API testing, CI/CD integration, quality gates, distributed-system testing.

    Related project

    Quality Assurance Layer for Distributed Systems 

    How do you validate a system whose failures live between services, not inside a screen?
